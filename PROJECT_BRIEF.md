# PROJECT BRIEF — All4Ruse v2

## Overview

All4Ruse v2 is a full rewrite of the All4Ruse platform, an events platform focused on Ruse, Bulgaria.

The platform brings local events together in one place so people can quickly discover what is happening in the city without searching across many Facebook pages and websites.

## Core purpose

Make it easy for people in Ruse to discover, browse, and follow local events.

## Audience

### Primary audience
- People living in Ruse
- People visiting Ruse
- People looking for cultural, social, family, nightlife, and community events

### Secondary audience
- Event organizers
- Venue owners
- Local businesses
- Future advertising and sponsorship partners

## Product goals for v2

- Redesign the platform with a higher-quality, more modern UI.
- Rebuild the codebase with better structure and maintainability.
- Improve SEO and performance.
- Make event data easier to manage and scale.
- Prepare for stronger admin workflows and future organizer features.
- Create a foundation for future monetization such as premium listings, sponsorships, ads, and ticket-related flows.

## Key product characteristics

The product should feel:
- local
- modern
- clean
- premium but accessible
- easy to browse
- content-first
- mobile-friendly

## Core user roles

### 1. Visitor
A normal user who wants to discover events.

Possible actions:
- Browse events
- Search events
- Filter by title/dates/tags/host/place
- Open event details
- Save or revisit interesting events later
- Authenticate

### 2. Admin
Internal role for managing the platform.

Possible actions:
- Create and edit events
- Manage categories and venues
- Feature selected events
- Moderate submissions
- Manage homepage/event visibility

### 3. Host (future or partial v2 scope)
A business or host who manages their own event submissions or promotions.

Actions:
- Create events
- Manage host profile
- Request featured placement

## Main content areas

- Events listing page (home)
- Event details page
- Admin area
- Legal pages
- Why all4ruse

## Success criteria for v2

- Clear and scalable architecture
- High-quality TypeScript codebase
- Better user experience than v1
- Faster iteration for future features
- Better content structure for local events
- Strong technical foundation for growth

## Non-goals for the first implementation

To avoid overbuilding too early, v2 should not try to solve everything in the first version.

Examples:
- Complex social features
- Over-engineered microservices
- Too many integrations before core UX is stable
- Large feature scope without validated need
